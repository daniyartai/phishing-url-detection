# PhishScan KZ

**Распознавание фишинговых ссылок с помощью машинного обучения**

## О проекте

PhishScan KZ по тексту ссылки за доли секунды определяет, фишинговая ли она, и объясняет своё решение. Страница при этом не открывается, поэтому проверка безопасна и встраивается в любой канал: Telegram-бот для клиентов, проверку ссылок в приложении и чатах банка, панель аналитика антифрода.

| Аспект | Описание |
|---|---|
| **Проблема** | Ущерб от интернет-мошенничества в Казахстане за 2025 год — 12,2 млрд ₸, фишинг — 18,5% случаев. Чёрные списки узнают о новых сайтах с опозданием |
| **ML-задача** | Бинарная классификация URL — «фишинговая» или «легитимная» — с объяснением вердикта |
| **Данные** | PhiUSIIL (UCI, 2024; 235 795 ссылок) и ежедневно собираемые свежие ссылки из OpenPhish, Phishing.Database и Tranco |
| **Метрики** | Recall при FPR ≤ 1% на свежих данных, PR-AUC, ROC-AUC, калибровка, время ответа |
| **Бизнес-эффект** | Проверка ссылки до перехода, в том числе в «нулевой час»: меньше похищенных данных и денег клиентов |

## Этапы проекта

Проект ведётся по методологии CRISP-DM; материалы каждого этапа — в отдельной папке.

| № | Этап | Папка | Статус |
|:-:|---|---|---|
| 1 | Бизнес-анализ (Business Understanding) | [`hw1_business_understanding`](hw1_business_understanding/README.md) | Готово |
| 2 | Анализ данных (Data Understanding) | `hw2_data_understanding` | Запланировано |
| 3 | Подготовка данных (Data Preparation) | `hw3_data_preparation` | Запланировано |
| 4 | Моделирование (Modeling) | `hw4_modeling` | Запланировано |
| 5 | Оценка результата (Evaluation) | `hw5_evaluation` | Запланировано |
| 6 | Внедрение (Deployment) | `hw6_deployment` | Запланировано |

## Структура репозитория

```text
phishing-url-detection/
├── README.md                     # обзор проекта и навигация
├── hw1_business_understanding/   # этап 1: бизнес-анализ
├── hw2_data_understanding/       # этап 2: анализ данных и поиск утечек
├── hw3_data_preparation/         # этап 3: признаки URL, разбиение, DVC
├── hw4_modeling/                 # этап 4: модели и эксперименты
├── hw5_evaluation/               # этап 5: свежие данные, «нулевой час», бизнес-оценка
├── hw6_deployment/               # этап 6: API, Telegram-бот, мониторинг
├── src/                          # общий код: сбор фидов, признаки, модели
└── data/                         # данные под управлением DVC (в git не хранятся)
```
