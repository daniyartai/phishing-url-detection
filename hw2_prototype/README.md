# PhishScan KZ: прототип продукта

Прототип решает две задачи:

- **основная — проверка спроса:** готовы ли банки интегрировать внешний API проверки ссылок и оплачивать его;
- **дополнительная — проверка технической реализуемости в реальных условиях:** качество модели на живых запросах, время ответа, стабильность сервиса.

На открытых данных техническая реализуемость уже подтверждена: модель обнаруживает 83% нового фишинга при доле ложных срабатываний 1%. Поэтому основная неопределённость связана со спросом. Контекст и бизнес-цели проекта — в [бизнес-анализе](../hw1_business_understanding/README.md).

## 1. Ключевая гипотеза

> Если мы предлагаем **REST API проверки ссылок с объяснением вердикта** для **банков второго уровня Республики Казахстан** в сценарии **автоматического ответа клиенту, приславшему подозрительную ссылку в чат поддержки**, то мы получим **конверсию в тестовое подключение** не меньше **20% (2 из 10 банков)** в течение **6 недель**, потому что **ответ оператора занимает минуты, за которые клиент успевает перейти по ссылке, а для интеграции достаточно одного рабочего дня и передачи только текста ссылки**.

| Элемент | Значение |
|---|---|
| A — продукт | REST API проверки ссылок: вердикт, вероятность фишинга и причины; время ответа — до 100 мс (p95) |
| B — сегмент | Банки второго уровня Республики Казахстан. Лица, принимающие решение, — подразделения по противодействию мошенничеству и развития цифровых каналов |
| C — сценарий | Клиент пересылает подозрительную ссылку в чат поддержки банка; чат-бот банка вызывает API и сразу отвечает клиенту |
| D — метрика | Конверсия в тестовое подключение: доля банков, выполнивших первый успешный запрос, от числа банков, получивших демонстрацию |
| E — целевое значение | Не менее 20% (2 из 10 банков) |
| T — срок | 6 недель с начала демонстраций |
| Обоснование | Ответ оператора занимает минуты, за которые клиент успевает перейти по ссылке; интеграция занимает один рабочий день и требует передачи только текста ссылки |
| Монетизация | Подписка: фиксированный ежемесячный платёж с лимитом запросов, тестовый период бесплатный. Ориентир цены — около 10 млн ₸ в год, или примерно 10% ущерба, предотвращаемого сервисом по оценке бизнес-анализа |

**Дизайн теста.** В течение 6 недель прототип демонстрируется 10 банкам: интерактивная документация API и отчёт о качестве модели на открытых данных. Банки, согласившиеся на тест, получают ключи к тестовой среде; фиксируются факт подключения и регулярность использования.

**Выбор сегмента.** Решение применимо и за пределами банковского сектора: для защиты сотрудников компаний от фишинговых писем и для сервисов, где пользователи обмениваются ссылками. Однако прототип проверяет один сегмент, иначе результат нельзя однозначно интерпретировать. Банки выбраны первыми: они несут прямые финансовые потери от фишинга, заказчик определён, а модель учитывает локальные бренды. Корпоративный сегмент — следующий этап.

## 2. Ключевые метрики

| Тип | Метрика | Методика измерения | Baseline | Целевое значение | Периодичность |
|---|---|---|---|---|---|
| Бизнес | **Конверсия в тестовое подключение (ключевая)** | Доля банков, выполнивших первый успешный запрос, от числа получивших демонстрацию | — | ≥ 20% (2 из 10) | Еженедельно |
| Продукт | Время до первого успешного запроса | Интервал между выдачей ключа и первым успешным ответом API | — | ≤ 1 рабочего дня | По каждому подключению |
| Продукт | Регулярность использования | Доля недель тестового периода, в течение которых банк отправлял запросы | — | ≥ 75% | Еженедельно |
| Бизнес | Готовность платить | Число банков, согласившихся на платный пилот по итогам теста | — | ≥ 1 | По завершении теста |
| Техническая | Полнота (Recall) при FPR ≤ 1% | Фишинговые ссылки OpenPhish за прошедшую неделю против доменов Tranco | 48% (модель без свежих данных) | ≥ 80% | Еженедельно |
| Техническая | Доля ложных срабатываний (FPR) | Доля легитимных ссылок, ошибочно отнесённых к фишинговым: ручная разметка случайной выборки запросов и обращения через `/feedback` | 1% (домены Tranco) | ≤ 2% | Еженедельно |
| Техническая | Время ответа (p95) | 95-й перцентиль времени ответа API | — | ≤ 100 мс | Ежедневно |
| Техническая | Доступность | Доля успешных проверок внешнего мониторинга | — | ≥ 99% | Ежедневно |

## 3. Состав прототипа

| Входит в прототип | Обоснование |
|---|---|
| REST API: `POST /check-url` — вердикт, вероятность и 2–3 причины; `POST /feedback` — сообщение об ошибке | Ядро продукта: банк самостоятельно встраивает API в свои каналы |
| Модель по имени хоста (LightGBM и символьные n-граммы) с порогом при FPR ≤ 1% | Лучший результат при корректной валидации на открытых данных |
| Сверка с фидом OpenPhish | Мгновенное обнаружение уже известных фишинговых адресов |
| Ежедневное обновление фидов, еженедельное дообучение, версия модели в каждом ответе | Без свежих данных полнота на фишинге 2026 года снижается с 83% до 48% |
| Ключи доступа, лимиты запросов, журнал обращений, еженедельный отчёт | Необходимы для расчёта метрик подключения и использования |
| Интерактивная документация (Swagger UI) | Служит демонстрацией для банка и инструкцией для разработчиков |

| Не входит в прототип | Обоснование |
|---|---|
| Telegram-бот и собственный клиентский интерфейс | Банк использует существующие каналы обслуживания |
| Модель по полной ссылке | Нет легитимных ссылок с путями: модель выучила бы формат ссылки вместо признаков фишинга |
| Загрузка страниц и признаки HTML | Риск для инфраструктуры и рост задержки; для проверки гипотезы не требуются |
| Раскрытие коротких ссылок | Требует изолированной среды; в прототипе возвращается статус «требуется проверка» |
| Развёртывание в контуре банка, SLA | Актуальны после подтверждения спроса |
| Масштабирование, полная автоматизация MLOps | Не влияют на решение по гипотезе |

## 4. Готовые компоненты и собственная разработка

**Готовые компоненты:** открытые данные PhiUSIIL, OpenPhish и Tranco; библиотеки scikit-learn и LightGBM; tldextract для разбора доменов; FastAPI с автоматической документацией Swagger UI; PostgreSQL и Docker Compose на арендованном сервере; внешний сервис мониторинга доступности.

**Собственная разработка** определяет ценность продукта:

- **Признаки сходства с казахстанскими брендами** (kaspi, halyk, egov, homebank) — готовые решения локальные бренды не учитывают.
- **Конвейер обновления данных и дообучения** — без него модель обнаруживает лишь около половины нового фишинга.
- **Интерпретация вердикта** — причины на понятном языке, которые банк может сразу показать клиенту.
- **Стабильный контракт API и версионирование моделей** — обновление модели не требует изменений на стороне банка.

## 5. Главный риск

**Длительное согласование внешнего сервиса.** Подключение внешнего API в банке согласует служба информационной безопасности, и процедура может занять больше 6 недель. Прототип проверяет, достаточно ли минимального объёма интеграции — передаётся только текст ссылки, подключение занимает один рабочий день, — чтобы банк согласился на тестовое использование.

## 6. Формат прототипа

REST API на арендованном сервере с интерактивной документацией. Фиды обновляются ежедневно, модель — еженедельно. Пример запроса и ответа:

```text
POST /v1/check-url
{"url": "hxxp://kaspi-bonus[.]top/login"}

200 OK
{
  "verdict": "phishing",
  "score": 0.94,
  "reasons": [
    "домен похож на kaspi.kz",
    "доменная зона .top часто используется для фишинга",
    "в адресе есть слово login"
  ],
  "model_version": "2026-11-16"
}
```

## 7. Критерии остановки теста

| Исход | Условие | Решение |
|---|---|---|
| Гипотеза подтверждена | За 6 недель API подключили не менее 2 из 10 банков; FPR ≤ 2%; время ответа ≤ 100 мс | Подготовка платного пилота |
| Результат неоднозначен | Подключился один банк | Одна дополнительная итерация: 4 недели, 5 новых банков |
| Гипотеза отвергнута | Ни одного подключения за 6 недель | Смена сегмента: финтех, МФО, маркетплейсы — организации с более коротким циклом принятия решений |
| Модель не готова | FPR выше 5% в течение недели или полнота ниже 70% две недели подряд | Приостановка тестовых подключений и доработка модели |
